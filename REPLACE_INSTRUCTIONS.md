# REMEDIUM CINEMA · установка обновления

Основа — GitHub, коммит 8c227ac7220fae0f8fe7f98cd18430b3a80fac2f. Более ранний доступный архив содержит 229 файлов и предшествует появлению Zero Two. Для замены использованы актуальные исходники GitHub.

1. Распакуйте ZIP. Содержимое уже расположено относительно корня, где лежат server.js и package.json.
2. В существующем репозитории откройте новую ветку от указанной версии. Загрузите перечисленные ниже файлы одним коммитом с сохранением структуры. Если основная ветка уже ушла вперёд, сравните изменения GitHub перед объединением.
3. В каталоге assets имя существующей папки с auth.css начинается с **четырёх пробелов**. Сохраните этот путь из ZIP. Express уже публикует его по обычному адресу /assets/auth/. Вторую папку создавать не требуется.
4. После объединения откройте Deploys существующего сервиса Render и проверьте, что успешное развёртывание относится именно к вашему коммиту. При выключенном автодеплое запустите деплой последнего коммита. Переменные и миграции для установки не нужны.
5. Для отката используйте Revert этого коммита и разверните результат. Инструкция и DELETE_FILES.md справочные.

## Результаты аудита

**Высокий приоритет.** Восстановление темы в navigation.js выполнялось в конце документа и выставляло глобальный атрибут только для Zero Two. Остальные темы получали оформление в основном внутри страницы профиля. Теперь обе HTML-точки входа используют один ранний загрузчик. Он принимает четыре поддерживаемых значения, затем существующий запрос аккаунта уточняет выбор. Настройки хранятся на сервере. Локально хранится название оформления для первой отрисовки. Уже открытые окна получают обновление через существующую синхронизацию. При первом входе на новом устройстве персональная тема становится известна после ответа сервера.

**Высокий приоритет.** Фон 002 собирался по-разному до и после получения профиля. Отдельно существовали нижнее изображение воды в фоне страницы, фиксированный псевдоэлемент с водой, верхний слой с героиней и нижний отступ профиля. В общей странице теперь используется один фон с верхней иллюстрацией и плавным переходом к тёмному цвету. Боковое меню сохраняет свою декоративную полоску под номером 002.

**Средний приоритет.** Последний блок CSS возвращал гостевой шапке яркую рамку и непрозрачную подложку. Общее правило кисточки снимало оформление кнопки. Убрана рамка шапки 002, для карандаша и кисти задана общая зона нажатия 44 × 44 пикселя. Неоновые контуры статистики и исходное изображение рамки аватара сохранены.

**Средний приоритет.** Загрузчик фото предлагался даже при закреплённом портрете. Теперь набор настроек фото зависит от активной темы, в том числе при её изменении в другой вкладке. В остальных темах доступна исходная фотография. Отображение чужого портрета учитывает настройку владельца, остальной интерфейс использует палитру посетителя.

**Средний приоритет.** На чужой странице набор действий менял число колонок. Теперь слева располагается «Сообщение», справа — статус или действие дружбы. При отсутствии дружбы переписка заблокирована согласно существующему серверному правилу. При подтверждённой дружбе правая кнопка открывает общих друзей только при доступном списке. Собственный профиль использует карандаш и кисть.

**Средний приоритет.** За окном «О проекте» оставалась видна рамка формы входа, а сам диалог имел лишь ограничение ширины. Пока открыт диалог, фоновая форма скрыта. Для содержимого заданы симметричные отступы, ограничение доступной высоты и внутренняя прокрутка. Оба абзаца сохранены.

**Навигация.** Удалены пункт «Кинозал», назначение ссылки на отсутствующий элемент и его участие в подсветке текущего раздела. Прямые ссылки на комнаты, навигация инструментов, выход и серверная маршрутизация сохранены.

**Технический долг.** В исходном index.html 260 вхождений !important и 21 блок @media, в исходном zero-two.css — 53 и 10 соответственно. Приоритеты старого оформления кинозала требуют явных правил для общих компонентов. В обновлении общие стили вынесены из файла одной темы. Массовая замена исторических правил потребовала бы отдельной визуальной регрессии плеера и каталога. Полный профиль памяти длительной сессии не снимался.

## Что проверено

- Синтаксис клиентских и серверных JS-файлов командой npm run check, отдельная проверка нового appearance.js и git diff --check.
- npm test — 3 из 3. Тесты используют изолированные HTTP, Socket.IO и PostgreSQL-совместимый движок PGlite, проверяют сохранение состояния после перезапуска. Прежние ожидания об удалённых темах обновлены по существующему серверному контракту.
- В Chromium проверены четыре темы на пяти страницах — главная, свой профиль, профиль друга, друзья, сообщения. Для каждой пройдены размеры 375×667, 390×844, 440×956, 956×440, 768×1024, 1024×768, 1440×900 и 1920×1080. Проверены ширина документа, ряд гостевых действий, тёмный цвет надписи «Сообщение», отсутствие инструментов владельца у гостя.
- Для каждой темы проверены открытие редактора, доступность управления фото, послания, отправка послания, голосование, рулетка и список фильмов. Проверены сохранение темы после перезагрузки и обновление уже открытого окна через Socket.IO.
- Для Zero Two на восьми размерах проверены границы меню, его открытие/закрытие на мобильной ширине, доступность выхода, пропорции аватара, корона возле имени, формы входа, регистрации, восстановления и габариты окна «О проекте». Успешный выход подтверждён запросом к тестовому серверу.
- Проверены пути локальных изображений из CSS с учётом регистра, 9 картинок тем декодированы браузером. Проверена отдача стилей и трёх фоновых изображений авторизации тестовым Express.
- На первом проходе браузерная проверка обнаружила светлый текст главной кнопки из-за специфичности старого селектора. После коррекции проверка цвета прошла для всех четырёх тем.

## Границы проверки

Физические iPhone и iPad, WebKit Safari, реальная экранная клавиатура, внешний видеосервис и производственный Render после установки не проверялись. Совпадение каждого пикселя, отсутствие любых утечек памяти и всех возможных ошибок не подтверждались. Полная комбинация каждого диалога с каждым размером не прогонялась. Рабочие аккаунты и производственная БД не использовались. В аккаунте по-прежнему четыре темы, а нейтральная палитра служит исходным оформлением входа при отсутствии сохранённой настройки.
